# MQTT Broker Configuration

## Overview

This document defines the MQTT broker configuration used by the IIoT Condition Monitoring System.

The firmware publishes telemetry data to the broker, while Node-RED, MQTTX, and Grafana subscribe to the same topics.

---

# Recommended Broker

HiveMQ Cloud

Alternative brokers:

- EMQX Cloud
- Mosquitto
- AWS IoT Core
- Azure IoT Hub

---

# Connection Parameters

| Parameter | Value |
|-----------|-------|
| Protocol | MQTT |
| Version | MQTT 3.1.1 |
| Transport | TCP |
| Host | <broker-url> |
| Port (Non-TLS) | 1883 |
| Port (TLS) | 8883 |
| Client ID | ESP32_001 |
| Username | <username> |
| Password | <password> |
| Keep Alive | 60 Seconds |
| Clean Session | true |
| QoS | 1 |

---

# Firmware Configuration

Example

```cpp
MQTT_BROKER
MQTT_PORT
MQTT_CLIENT_ID
MQTT_USERNAME
MQTT_PASSWORD
```

These parameters are stored in:

```
firmware/include/config/mqtt_config.h
```

---

# Authentication

Authentication uses username and password generated by the cloud broker.

Never commit credentials to GitHub.

Store credentials inside configuration headers or environment variables.

---

# TLS Configuration

Production

- TLS Enabled
- Port 8883
- Root CA Certificate Required

Development

- TLS Disabled
- Port 1883

---

# Client ID Convention

```
ESP32_001
ESP32_002
ESP32_003
```

Each device must have a unique Client ID.

---

# Reconnection Policy

If broker connection is lost

1. Detect disconnect
2. Wait 5 seconds
3. Retry connection
4. Re-subscribe to topics
5. Resume publishing

---

# Publish Interval

```
2 Seconds
```

Configurable from

```
config.h
```

---

# Broker Responsibilities

- Authenticate clients
- Receive telemetry
- Route messages
- Store retained messages
- Deliver subscribed topics
- Manage QoS
- Maintain client sessions

# Production Recommendations

- Enable TLS
- Use QoS 1
- Unique Client IDs
- Strong Passwords
- Separate Topics
- Enable Auto Reconnect
- Monitor Broker Status
- Backup Dashboard Configurations

---

# Future Expansion

The broker can support multiple industrial devices simultaneously.

Example

iiot/factory1/machine1

iiot/factory1/machine2

iiot/factory1/machine3

iiot/factory2/machine1

Each device publishes independently while sharing the same MQTT broker.
